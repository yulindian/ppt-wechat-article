# 公众号草稿导入与验收

当用户要求“自动导入”“存公众号草稿”“把课件文章放入后台”时读取本文件。通过已登录的公众号网页编辑器操作，无需 AppSecret。这是智能体执行的后台工作流，当前本地生成脚本并不自动控制浏览器。

## 选择与准备

1. 先读取并遵循当前可用的浏览器或电脑控制工具说明。核实目标公众号名称和文章；有多个目标账号且上下文不能判断时询问用户。
2. 确认本地包含标题、摘要、封面、`公众号文章导入稿.docx`，DOCX 图片数应为最终 PDF 页数加 2。检查图片、导语及结语页数。
3. 用户已指定更新某份草稿时更新该份。否则先查看草稿箱是否已有本次任务生成的同一篇文章，避免重试创建重复稿；仅同名但无法确认身份时新建或请用户确认，不覆盖无关稿件。
4. 当前后台实测“文档导入”允许不超过 15 MB 的 DOCX；每次以界面实际限制为准。超过上限时调整课件页图压缩质量后重新生成并目视核对，保留原稿。不能导入时使用后台图片上传补传，不退回反复尝试已失败的本地图片粘贴。

## 导入与填写

1. 打开目标公众号的图文编辑器，选择“文档导入”，上传完整 DOCX。导入会替换当前正文，因此先确认正在操作的是本次新稿或已授权更新的草稿。
2. 等待导入完成，检查首尾引导图和课件页图。Word 导入可能把文件名写成文章标题，因此**导入完成后**重新填入 `公众号标题.txt` 的正式标题。
3. 默认将 `发布信息.txt` 中的候选摘要填入摘要栏；用户要求不填简介/文章摘要时，按其要求保持空白。若填写内容超出后台字数上限，压缩后核实事实与资源清单未变。名片简介和文章摘要是不同字段，不混淆；本地仍可保留候选摘要。
4. 上传 `公众号封面图.png`（1880×800，2.35:1）。先核实横版铺满、标题清楚完整，不能使用“完整首页缩在中间、四周大留白”的旧版封面。再单独检查1:1方形取景位置；方形默认位置可能偏右，须移动裁切框优先保留标题。不能仅凭本地检查跳过后台检查，也不能缩小横版主体迁就方形。更换本地封面后要在已有草稿中重新上传、保存并复核，不重复新建文章。
5. 用户未指定插入名片时，开头图下方、结尾图上方保留名片空位。用户要求插入时：在开头图之后的独立空段落、结语之后且结尾图之前的独立空段落分别定位光标；通过工具栏“账号名片”（窄窗口可能在“…”中）搜索并核对账号名称、头像及账号身份，选中后点“插入”。两处使用同一目标账号，简介默认不填。不用截图或普通图片伪装名片，不自行添加联系方式。先完成Word导入再插名片；重新导入会清除之前的名片，必须在两处重新插入，并检查没有重复或插错位置。用户未指定账号且存在歧义时先确认，不按同名搜索结果随便选择。
6. 点击“保存为草稿”。等待保存结果；不点击“发表”。

## 必须重新打开后验收

保存成功提示只是中间结果。刷新编辑页或从草稿箱重新打开，检查：

- 正式标题、封面及用户要求的摘要状态（填写或空白）都保留，历史版本或保存状态确认本次保存。
- 正文图片数为 PDF 页数加 2；图序与源 PDF 一致，首、中、末页能显示，无空白或破图。必要时逐页滚动核对，不把占位元素数量当成成功上传数量。
- 预览组件为可编辑文字，上下留白；导语首行缩进；资料清单加粗，与“下面按照上课顺序完整展示课件。”同段，正文不显示 Markdown 星号或 HTML 源码。
- 结语为“以上是最终PPT的完整预览，共X页”；如已要求名片，则恰好两张真实账号名片、目标账号正确、位置分别为开头图后及结尾图前，简介按要求留空。未要求时检查两处留位。账号名片另计，不加进“课件页数＋2张引导图”的正文图片数量。
- 未执行手机真机预览时，在结果中明确标为未检查；不要将桌面编辑器结果写成手机验收通过。

每篇记录目标账号、草稿编号、保存结果、重新打开后的图片数量与残留问题。长时间导入或保存失败时先重新观察状态，确认前一次是否已生效再重试；同一失败经一次有依据的修正仍失败时停下交代具体错误，避免连续创建或覆盖草稿。

## 已验证的适用范围

2026-11-08 在本机 WeChat Publisher 1.3.0 与公众号后台测试：复制的本地图片地址为 Obsidian `app://`，直接粘贴不能持久保存图片；改为嵌入图片后编辑区可显示，保存后仍被过滤。后台 DOCX 导入的 18 页课件和两张引导图，共 20 张正文图片，在保存并刷新后保留，缩进、加粗和文字组件也保留。此结果用于选择当前默认路径，不保证其他版本或账号行为相同。
